# Mod • → Add — end-to-end verification

**Sprint:** `docs/plans/2026-06-02-bulletin-mod-add-sprint.md` (item 6)
**Date:** 2026-06-02
**Status:** verified by automated tests (the loop is proven leg-by-leg in-process)

## What "the loop closes" means

A host on a live studio bulletin opens **Mod • → Add**, picks a model, and the model is
*downloaded onto the pod and shown as installed* — without any new runtime infrastructure. The
queued model rides the existing gen rail: it lands in the next `/make`'s `spec.models`, comfyrunner
downloads what's missing, and the completion webhook reconciles `Materia.installedModels`, which
`Mod • → View loadout` reads back.

```
Mod • → Add → pick                       (bulletin picker)
  → PodSession.pendingModels               queued tail: "Queued: SDXL"
  → /make: _enterExecute stamps state.pinnedModels, clearPendingFor   (dispatch)
  → ExecuteFlow._submit → inceptor.initiate({ pinnedModels })          (flow)
  → Actum.pinnedModels                     (first-class typed field)
  → RunPodCursor.run(actum) → compile(modus, aditus, actum.pinnedModels)  (cursor)
  → Compiler unions into spec.models       (deduped by id)
  → comfyrunner downloads missing weights; reports executio.modelsInstalled
  → executionWebhook set-unions into Materia.installedModels           (reconcile)
  → Mod • → View loadout reads installedModels → shows the model installed
```

## Why this is verified by tests, not a live transcript

A true live boot needs a real Telegram bot token (long-poll), a Mongo instance, and a (fake) GPU
pod — none of which produce a *deterministic, re-runnable* proof. Instead every leg of the loop is
pinned by an automated test that runs in CI. A live `DEV_FAKE_POD` smoke test (below) remains a
useful manual sanity check, but the correctness guarantee is the test suite.

## Leg-by-leg proof

| Leg | Proven by |
|-----|-----------|
| Pick → queued onto the session loadout (FCFS base-replace, LoRA accumulate, dedupe) | `tests/unit/allocutio/bulletin/PodSession.test.ts` |

| **Flow bridge:** `state.pinnedModels` → `inceptor.initiate({ pinnedModels })` | `tests/unit/flow/ExecuteFlow.test.ts` |
| **Cursor bridge:** `actum.pinnedModels` → `compile(…, pinnedModels)` | `tests/unit/crystal/RunPodCursor.test.ts` |
| Compiler unions pinned models into `spec.models`, deduped by id | `tests/unit/crystal/Compiler.test.ts` |
| Webhook set-unions `executio.modelsInstalled` into `Materia.installedModels` | `tests/unit/crystal/executionWebhook.test.ts` |
| `Mod • → View loadout` renders installed + queued from the snapshot | `tests/unit/allocutio/bulletin/BulletinView.test.ts` |

Run them all:

```bash
npm run test:crystal                                  # crystal + compiler + webhook + cursor
npx tsx --test 'tests/unit/allocutio/**/*.test.ts'    # bulletin + adapter
npx tsx --test tests/unit/flow/ExecuteFlow.test.ts    # flow bridge
```

## Optional live smoke test (`DEV_FAKE_POD`)

For a human sanity check against `noema_fake.intellae` (simulated pod, $0):

1. Boot with `DEV_FAKE_POD=1` (see `scripts/run-crystal.sh`) pointed at the fake DB.
2. `/make` to spawn a studio bulletin; confirm the warm window.
3. **Mod • → Add** → pick a migrated LoRA → confirm the body shows `Queued: <name>`.
4. `/make a portrait` → the `FakeRunPodClient` simulates the download; the gen completes.
5. **Mod • → View loadout** → the model now reads as installed (no longer queued).

Expected: the picked model appears in the dispatched spec's models, the fake webhook reconciles
`installedModels`, and View loadout reflects it. (Same chain the tests above pin.)
