## What exists and works

### The ring

`src/container.ts` creates a fully wired `Ring` — every primitive has a Mongo
implementation backed by `noemaplane.*` collections:

### Execution rail

- `ActumInceptor` → `Cursorum` → cursor `reserve()` + `run()`
- `ActumCompletor` → `Signorum.settle()` → `Nexus.emit()`
- Ledger hooks: `hostCut` (20%), `spellRoyalty` (10%), `modelRoyalty` (5%), `referralSplit`, `sessionSpend`, `platformSkim`
- `SimpleCursorum` with cursors registered: `runpod`, `tessera`, `openai`, `huggingface`

### RunPod pipeline (the whole thing)

- `SecurePodClient` — provisions RunPod SECURE pod, SSHes in, polls ComfyUI, uploads output
- `Praefectus` — warm pod pool scheduler; `findWarm()` routes jobs to idle matching-image pods
- `WarmPodClient` — submits to an already-warm pod (bypasses cold-start provisioning)
- `RunPodCursor` — compiles Modus + aditus → `DeploymentumStore.upsert()` → `client.submit()` → stamps `Actum.deploymentHash`
- `TesseraCursor` — session-scoped execution via Modo tessera signa

### Compiler

- `Compiler` — resolves models from `Intellarum` registry (fallback to template URL), injects seed into workflow, returns `{ hash, spec }`
- `WorkflowTemplateRegistry` — loads JSON workflow templates from `src/crystal/workflows/`
- `flux-schnell-v1.json` — FLUX.1 Schnell ComfyUI workflow template; model IDs use canonical `intella.*` namespace

### Platform wiring (Telegram)

- `TelegramAllocutio` — receives Telegram updates, resolves identity, dispatches to FlowRouter, sends replies
- `FlowRouter` — intent-based flow dispatch (enter/handle/clear); routes to registered `Flow` implementations
- `MongoFlowContextStore` — persists flow state across messages; write-through cache + `hydrate()` on startup
- `ExecuteFlow` — the core generation flow: collect aditus → `ActumInceptor.begin()` → wait for webhook → reply with result
- `webhookRouter` — Express router: RunPod completion webhook → `ActumCompletor` → `FlowRouter.handleActumComplete()`

### Seeds (registered on every startup)

- `CANONICAL_MODI` — canonical Modus list (`src/crystal/seeds/modi.ts`)
- `CANONICAL_INTELLAE` — 4 FLUX Schnell models (`src/crystal/seeds/intellae.ts`)

## How to run

```bash
# Required env vars
BOT_TOKEN=...              # Telegram bot token
MONGODB_URI=...            # Atlas or local (reads/writes noemaplane.*)
RUNPOD_API_KEY=...         # RunPod API key
RUNPOD_GPU_TYPE_IDS=...    # Comma-separated, e.g. "NVIDIA GeForce RTX 4090"
RUNPOD_IMAGE_NAME=...      # e.g. "stationthis/flux-comfyui-runtime:v1"
RUNPOD_WEBHOOK_URL=...     # Where the runner POSTs completions (your server URL)
OPENAI_API_KEY=...         # Optional — enables openai cursor

# Optional
RUNPOD_CLOUD_TYPE=SECURE   # default SECURE
RUNPOD_KEEP_WARM=true      # default true — pods stay warm between jobs
TELEGRAM_WEBHOOK_URL=...   # If absent, falls back to long polling

# Run
npx tsx src/index.ts
```

Tests: `./scripts/run-with-env.sh npx tsx --test 'tests/unit/**/*.test.ts'`

## What is NOT done

### Discord

No `DiscordAllocutio`. The old JS Discord platform (`src/platforms/discord/`) is
untouched. Discord users still go through the legacy JS stack.

### Web frontend and REST API

`src/platforms/web/frontend/` is a Vite/Vue app untouched by this branch.
The crystal has no REST API routes for tools, spells, users, collections, etc.
Only the RunPod completion webhook is exposed from the crystal side.

### JS service retirement

`src/core/services/` (~50 JS files) still exists. The crystal runs alongside
it on a separate DB namespace (`noemaplane.*`). Nothing is deleted yet.
Retirement happens after ring is promoted to production — not before.

### Data migration

Production data lives in `noema.*`. The crystal reads/writes only `noemaplane.*`.
Migrating user accounts, generation history, credits, etc. is a future step
that requires a promotion plan and a cutover window.

### Conversation threading (Colloquium/Dictum)

`MongoColloquium` and `MongoDictum` exist and are tested. The `ExecuteFlow`
does not yet create `Dictum` records or thread conversations through
`Colloquium`. This is Phase 8 in the master plan — the primitives are ready,
the flow wiring is not.

### Training as a Flow (Phase 10)

Training is still the legacy JS pipeline. The master plan has a clear design
for it (`docs/crystal-master-plan.md` Phase 10) but zero implementation.
